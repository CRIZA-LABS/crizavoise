# CLAUDE.md — CrizaVoise

**CrizaVoise by Criza Labs**: offline invoicing/billing desktop app. This file is the context for future sessions. Read `CrizaVoise_Prompt.md` (local working brief, gitignored) for the full 3-phase plan.

## Stack
- **Flutter 3** desktop: Windows first, then Linux and macOS. The Android/iOS/web folders exist but aren't shipped.
- **State:** Riverpod (`flutter_riverpod`). Repositories live in `lib/repositories/` (SQLite implementations in `sqlite/`), wired in `lib/providers/`.
- **Data:** SQLite via `sqflite` + `sqflite_common_ffi`. Each company gets its own DB file (`invoice_manager*.db`) in the app-support dir. The company registry lives in SharedPreferences.
- **PDF:** `pdf` + `printing`. Templates are in `lib/services/pdf/`. The viewer is `printing`'s PdfPreview (`lib/widgets/pdf_bytes_viewer.dart`). Default colours come from `lib/services/pdf/pdf_brand.dart`; don't use blue.
- **i18n:** ARB files in `lib/l10n/` (en is the template; es, fr, hi, gu, ne, zh, bo). Missing keys fall back to English. New strings should get hi and gu translations.
- **Desktop window:** `window_manager`.

## Brand & tokens
- Name **CrizaVoise** (capital C and V). The credit line is "CrizaVoise by Criza Labs". Never imply Criza Labs wrote the original codebase. Rules are in `docs/brand.md`.
- Logo system = the **Criza family**: the app mark is "the bill being printed" (Stamp-red printer slot, Paper bill with a zig-zag edge, total ending in the Criza red dot) in **dark (Ink tile) and light (Paper tile)** versions. Palette = "Ink · Paper · Stamp", no blue (Stamp red is the UI primary, Ink the app bars); `BrandAssets.markFor(brightness)` picks one. The lockup "CRIZA VOISE." is built from the Criza master lettering exactly like "CRIZA LABS.". Exports live in `brand-kit/`. Generated by `tool/brand` (`npm install && npm run build`, needs `D:AIProjectCRIZA`). Paths are in `lib/theme/brand_assets.dart`; rules are in `docs/brand.md`. The Windows `.ico` (14 sizes) and web icons come from `tool/brand`, NOT flutter_launcher_icons.
- **Tokens: `lib/theme/tokens.dart` is the single source** (CvColors light/dark, CvType, CvSpace, CvRadius, CvElevation, CvMotion, CvZ, plus the `CrizaTokens` ThemeExtension). `lib/theme/app_theme.dart` builds ThemeData from them. Don't hard-code colors in widgets.
- Fonts: Inter (body) and Bricolage Grotesque (headings) as variable TTFs, with Noto Devanagari/Tibetan fallbacks. All are OFL/permissive and listed in `THIRD_PARTY_NOTICES.md`.
- Contrast is enforced by `test/theme_contrast_test.dart` (WCAG AA, both themes).

## Decisions (don't revisit without asking the owner)
- Version **1.0.0**. App ID **`dev.criza.crizavoise`**. Binary **`crizavoise.exe`**. Windows data dir **`%APPDATA%\Criza Labs\CrizaVoise\`** (it comes from `windows/runner/Runner.rc` CompanyName/ProductName; changing those moves user data).
- **Legacy data migration:** `lib/migration/legacy_data_migration.dart`.
  - `main()` runs `runCopyPhase()` before any DB or SharedPreferences access. It zips the old dir into `backups/` and then COPIES it.
  - `SplashScreen` calls `finalizeAfterSuccessfulOpen()` after the DB opens, which deletes the old dir.
  - The log is `migration.log` and the marker is `.cv_migration.json`, both in the data dir.
  - `LegacyAppPaths` (with its test) is the **only** place old-product names may appear in code.
- **License:** a proprietary `LICENSE` (Criza Labs + AbrarAli S). The upstream MIT notice is kept word for word in `THIRD_PARTY_NOTICES.md`. Both are bundled as Flutter assets and installed next to the exe via CMake.
  - In the app: Settings → About → Open-source licenses (`lib/screens/settings/licenses_screen.dart`).
- **Emails only in `lib/common/app_config.dart`:**
  - `supportEmail` contact@ (support), `infoEmail` info@ (general/legal), `businessEmail` connect@ (business/licensing).
  - Open them via `lib/utils/contact_links.dart` (mailto + subject; support also gets version/OS/installation ID).
  - Packaging metadata (deb maintainer) is the one unavoidable exception.
- **Licensing (offline):** 30-day trial, then 6m / 1y / lifetime keys. Code in `lib/licensing/` (codec, service, machine_id, license_keys).
  - Keys are Ed25519-signed; private keys are in gitignored `.secrets/` (NEVER commit). Issue keys with `dart run tool/license/generate.dart` (see docs/licensing.md).
  - On expiry the app is view-only: `ensureCanCreateDocuments` (lib/widgets/license_banner.dart) gates invoice, draft and purchase-bill saves. `LicenseStrip` sits above the dashboard.
  - Tests use an in-memory store automatically (FLUTTER_TEST), never the registry.
  - **Admin app:** `tool/license-admin` (Node 22+, Hono, WebCrypto, node:sqlite; data in `.secrets/admin/`; `npm start` → http://127.0.0.1:8787; `npm test`). Written to move to Cloudflare Workers + D1 + Access later. Keys must stay byte-compatible with `license_codec.dart`.
  - **Online check:** `lib/licensing/online_check.dart`, dormant while `AppConfig.licenseCheckUrl` is null. Signed status "CVSTAT1|" from `/api/v1/status`, on each app start when online. Lenient: offline or no answer keeps the current state; only revoked/moved → `LicenseKind.licenseRevoked`; a later active answer undoes it.
- **Accounts:** first run → `CreateAccountScreen` replaces the seeded admin/admin. Recovery codes are stored hashed in `users.recovery_hash` (DB v60). Forgot password = recovery code or a Criza Labs reset code (`generate.dart reset`).
- **No network calls without the owner's OK.** The update check is disabled (`UpdateConfig`). The FAQ is bundled-only. Analytics, donate and review links were removed. The only remaining request is the test-build clock (`TestBuildConfig.clockUrl`), which runs only on CI test builds.
- **Legal:** `TERMS.md` + `PRIVACY.md` (bundled assets, installed next to the exe). `TermsAcceptanceScreen` gates login until `AppConfig.termsVersion` is accepted (stored per installation via `TermsService`); bump the version when either document changes materially. Have a lawyer review before charging.
- PDF credit is `AppConfig.pdfCredit` ("Powered by CrizaVoise · criza.dev"), hidden by `SettingKey.showInvoiceFooterBranding`.

## Future direction (design for it now)
The owner plans an **online backup option**, a **web version** and a private **licence-admin web app** (criza.dev subdomain). Until then the app stays offline, and any network call still needs the owner's OK. When building features:
- **Data:** go through the repository interfaces (`lib/repositories/` + Riverpod providers); never call sqflite from widgets. A cloud/REST repository should be able to drop in.
- **Platform code:** keep `dart:io`, `dart:ffi`, win32 and file paths in small platform files (e.g. `lib/licensing/machine_id.dart`) that can be swapped with conditional imports for web. `AppEditionConfig.isCloud` is the existing cloud hook.
- **Backups:** keep them portable (DB file + JSON export, every table listed in `BackupManager`), so they can be encrypted client-side and uploaded later.
- **IDs:** use UUID string IDs (already the pattern) so records can sync without clashes. New timestamp fields should be UTC ISO strings (older ones are local time).
- **Licensing:** the key format (`CV1.`, versioned payload) can carry new fields such as an account ID; leave room for an optional online check.

## Conventions
- Package imports: `package:crizavoise/...`.
- New UI strings go to `lib/l10n/app_en.arb` (with `@key` metadata when placeholders are used), then run `flutter gen-l10n`.
- Keep business logic (invoice math, tax, numbering, storage, exports) unchanged during redesign work.
- Git: work on branch `crizavoise`. The `upstream` remote is the original project, so **never push to it**.
